# 微信公众号OCR采集器 (V3.0.0)

通过**鼠标点击 + OCR 识别 + AI 视觉**操作微信 PC 版，自动采集公众号历史文章、互动数据与评论区的自动化工具。

- 依赖微信 PC 版：**4.1.11.24**
- 纯标准库 GUI（tkinter），OCR 用 rapidocr_onnxruntime，AI 视觉用豆包（doubao-seed-2-0-mini）
- 不依赖 tool.exe 等外部工具，直接操作微信界面

---

## 一、功能概览

| 功能 | 说明 |
|------|------|
| 文章采集 | 按公众号批量采集文章中标题、时间、链接，保存完整 HTML |
| 互动数据 | 阅读 / 点赞 / 转发 / 喜欢 / 评论数（OCR + 豆包识图双通道） |
| 原创 / IP属地 | 从文章 HTML 提取（copyright_logo / ip_wording） |
| 评论采集 | 一级 + 二级评论，自动展开"回复"，层级 / 父级关系 / 回复数 |
| 评论 CSV | 14 列：采集时间(精确到秒)、文章链接、名称、地区、时间、点赞、正文、层级、置顶、作者回复、作者点赞、评论ID、父级评论ID、回复数 |
| 乐观并发 | 不等待 4 指标识别结果，评论采集提前并行进行 |
| 自定义时间范围 | 全部 / 当天 / 近一周 / 近一月 / 近一年 / 自定义日期 |
| 无额度提示 | 豆包余额不足时明确提示并自动停止后续调用 |

## 二、环境依赖

| 依赖 | 用途 |
|------|------|
| Python 3.11+ | 运行环境 |
| tkinter（内置） | GUI 界面 |
| rapidocr_onnxruntime 1.4.x | 屏幕 OCR 识别 |
| requests | 抓取文章 HTML |
| Pillow（PIL） | 截图 / WebP 压缩 |

安装：
```bash
pip install rapidocr_onnxruntime requests Pillow
```

> 豆包 API Key 需在火山方舟控制台申请（模型 `doubao-seed-2-0-mini-260428`），填入界面"豆包API Key"栏。

## 五、界面说明

布局：**左侧控制区（600）+ 右侧任务区（600）**，窗口 1240×700（小屏自动适配）。

### 左侧控制区

- **控制台（日志）**：下方实时显示运行日志
- **采集控制**（上方）：
  - 索引范围：起始 / 结束
  - 时间范围：全部 / 当天 / 近一周 / 近一月 / 近一年 / 自定义（日历选择，默认近 3 天）
  - 每公众号最大文章采集数量：空 = 无限
  - 采集 4 指标 / 采集阅读数：复选框
  - 一级评论采集数量：**空 = 无限采集，0 = 不采集，>0 = 采 N 条**
  - 每级二级评论采集数量：**空 = 无限展开，0 = 不展开，>0 = 每条一级下最多 N 条**
  - 滚动距离 + 测试滚动（文章列表）
  - 评论区滚动 + 测试滚动（点位 23）
  - 豆包 API Key（密码输入 + 显示开关）
  - 开始按钮 + 点位设置按钮

### 右侧任务区

input 数据表格：索引 | 链接 | 公众号名称 | 状态（双击编辑、操作列删除、底部重置/新增），支持横/纵向滚动。

## 六、采集流程

### 6.1 点击开始后

1. 校验设置（索引/时间/数量格式）
2. 检查微信窗口（找不到 → 弹窗提示，不开始）
3. 启动 ESC 监听（按 ESC 立即停止）
4. 微信靠左半屏 + main 靠右半屏，任务栏自动隐藏（退出恢复）

### 6.2 单任务流程

```
① 聚焦微信窗口 → 点位1(搜索栏) → Ctrl+Shift+W → 输入1 → 删除 → 点位2
② 点位3(搜索按钮) → 粘贴任务链接 → 回车 → 等5秒
③ 点位4(作者名称) 连续点击 → 严格三态检测(非全白→全白) → 进入文章列表页
④ 文章列表 OCR 循环（见 6.3）
⑤ 点击文章卡片 → 等5秒 → 复制链接(点位18, 固定点无OCR) → 采集4指标截图
⑥ 乐观并发: 立即点击点位21打开评论区 + 评论采集(与4指标识别并行)
⑦ 7指标识别结果返回(留言=0则停止评论采集并清理误采集)
⑧ 后台抓取文章(fetch_article 标题/时间/HTML + 原创/IP属地) → Ctrl+W关闭
```

### 6.3 文章列表 OCR 循环

```
循环：
  1. OCR 识别点位5/7 区域卡片（命中时间格式即卡片）
  2. 依次点击每个卡片 → 复制链接（点位18）→ 采集 → Ctrl+W
  3. 时间范围检测 / 最大数量检测 → 退出循环
  4. 全部点完 → 滚动配置距离 → 回到循环开头
停止：范围不可达（顶部已早于范围开始）→ 直接结束该任务
```

### 6.4 评论采集循环（评论区打开后）

```
循环：
  1. 截图点位22/23 区域（截图前鼠标移开点位23）
  2. 与上一张对比：相同 → 跳过识别继续滚动；连续3次相同 → 到底停止
  3. OCR 检查"回复"按钮（灰色）→ 依次点击展开二级评论
  4. 重新截图 → 并行执行：豆包识别评论(JSON) + OCR 名称行层级校准
  5. 跨轮去重（内存记录已识别评论ID，滚动重复不写）→ 写评论CSV
  6. 滚动配置距离 → 回到循环开头
停止：连续3次截图相同 / 一级达到上限 / 豆包确认留言=0（自动清理误采集）
```

### 6.5 时间识别规则

星期X / 周X / 礼拜X、今天、昨天、前天、X天前 / X小时前 / X分钟前、年-月-日（2026-08-05）、月日（8月21日）。

### 6.6 失败处理

任一步走不通 → 标记 error（写入 input.csv 状态）→ 下一个任务：
缺少点位 / OCR 失败 / 无卡片 / 复制链接失败(3次) / 抓取文章失败 / 作者名称检测超时。

## 七、数据文件

### 7.1 collected.csv（文章采集记录，14 列）

```
公众号名称, 日期, 标题, 链接, 阅读, 点赞, 转发, 喜欢, 评论, 写入时间,
互动截图, 阅读截图, 是否原创, IP属地
```

### 7.2 comments.csv（评论采集记录，14 列）

```
采集时间(精确到秒), 文章链接, 名称, 地区, 时间, 点赞数量, 正文, 层级(1/2),
是否置顶, 是否作者回复, 是否作者点赞, 评论ID(16位哈希), 父级评论ID, 回复数量
```

- **评论ID**：名称|地区|时间|点赞|正文|层级 → MD5 前 16 位
- **父级评论ID**：二级评论含"回复某某：" → 父=某某；否则父=所属一级评论
- **回复数量**：该条评论被多少二级回复

## 十一、注意事项

1. 采集前请保持微信已登录、处于正常界面
2. 程序运行期间任务栏隐藏，退出自动恢复（勿强杀进程，否则需手动恢复任务栏）
3. 复制链接依赖剪贴板，请勿在采集时手动使用剪贴板
4. 微信版本变化可能导致点位偏移，需重新采集点位（可用【预览】验证坐标）
5. 评论采集依赖豆包 API，请确保账号有额度
6. 采集速度受微信响应与豆包识别耗时影响，属正常现象
